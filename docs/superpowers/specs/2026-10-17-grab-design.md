# 素食店家 Grab 查核

使用者確認：不限定飯店，只需知道店家是否有 Grab。沿用既有 46 家餐廳及卡片，不新增飯店叫餐流程。

採逐分店證據模型，避免布林值將查無資料誤判為沒有。狀態為 `official-link`（官網提供分店 Grab 入口）、`reported`（有平台資料、明確外送回報或已註記限制的搜尋索引線索，仍需 App 確認）、`historical`（僅舊資料）、`unverified`（待確認）、`closed`（專案已記錄歇業，停止外送推薦）。每筆保留搜尋名稱、分店地址、查核日、證據類型、來源與說明。查核日不是證據發布日。

官方分店入口顯示在卡片，可直接開啟；沒有入口時提供 GrabFood 越南官方入口及可複製搜尋名稱。不得猜 merchant ID、偽造搜尋直達或把叫車、Grab-and-go、ShopeeFood 當 GrabFood。官網連結不代表已驗證 App 接單；配送範圍、價格、時段以 App 收件地址為準。歇業卡片不提供外送動作。

附近頁提供 Grab 證據篩選，與區域、飲食、距離、營業狀態合併；顯示可移除條件並支援重設及新版還原。每日與附近共用卡片，因此兩處都可讀查核結果。未新增每日篩選以免增加手機控制項。

研究放獨立 JSON，build-data.py 嚴格檢查 ID 全覆蓋、日期、狀態及 HTTPS 網域後輸出 data.js。研究報告列出全部 46 家、調查限制和排除來源。新版快取升為 v24，更新 README 與交付 ZIP。

驗證涵蓋證據完整性、官方連結分店不混用、篩選組合、缺資料降級、歇業不推薦，以及手機卡片、複製成功／失敗、篩選清除、新版狀態還原與既有離線流程。

## 使用者後續要求：標籤與搜尋

使用者要求加入「有 Grab」標籤及搜尋條件。僅有官方入口者在卡片頂端顯示綠色標籤，回報／舊資料／待確認／歇業不加此標籤。搜尋 Grab、GrabFood、有 Grab 對應官方入口條件，可與區域／全素關鍵字組合，適用每日與附近。沿用進階篩選保留線索查詢。離線版本升為 v25，ZIP 同步。
