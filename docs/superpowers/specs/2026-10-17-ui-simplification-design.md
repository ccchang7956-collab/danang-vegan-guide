# 全站 UI／UX 資訊分層優化提案

狀態：使用者已確認設計方向；實作與驗證記錄見 ../../ui-simplification-2026-10-17.md。

## 現況與問題

檢查 index.html、app.js、styles.css、mobile.css、ux.js 相關介面結構，並以 Chrome 390 × 844 擷取每日、附近餐廳、店家卡片。

- 附近頁第一張卡片上緣位於頁面約 972px，初始畫面看不到餐廳；搜尋回饋、定位說明、Grab 長段說明佔據大量空間。
- 抽查第一張店家卡高約 637px，同時有多個行動按鈕、Grab 區塊、店家詳情與來源區塊。
- 附近頁有多處「查看結果」；收藏、排序、列表／地圖切換與其他篩選分散。
- 每日頁的參考位置和完整搜尋工具先於行程出現，手機首屏看不到路線內容。
- styles.css 與 mobile.css 多次覆寫相同選擇器，後續功能容易增加不一致間距與排列。

## 方案比較

1. 僅調字級與留白：變更小，但無法解決操作分散和內容過長。
2. 資訊分層與操作整併（建議）：保留米白深綠與既有功能，調整閱讀順序、共用卡片和篩選區；以較低回歸風險解決主要問題。
3. 重做全站導覽與視覺風格：影響範圍大，增加旅行前重新學習成本，暫不採用。

## 設計

### 全站共通

沿用五個主要功能和現有品牌；縮短頁首與非必要宣傳文案，統一標題、輔助文字、卡片間距、按鈕與展開控制。每區只保留一個主要動作。狀態訊息簡短呈現，詳細解釋按需展開；重要飲食、歇業、地址衝突與休息警告持續顯示。

### 每日行程

閱讀順序為日期、當日摘要、行程路線、用餐安排／餐廳。餐廳搜尋改為明確命名的可展開工具區，參考位置、半徑、用餐時間集中管理；保留簡短的目前條件摘要。地圖提供清楚入口，手機不讓大地圖阻擋行程內容。保留早餐／午餐／晚餐搜尋及跨頁帶入條件。

### 找餐廳

頂部以搜尋框為主，參考位置與距離同組。常用條件提供「全素」「有 Grab」「收藏」切換；有 Grab 僅對應有官方入口的三家，與現有搜尋語意一致。其他日期、時段、區域及查核狀態收在更多條件。

將搜尋摘要、結果數、排序、列表／地圖集中到結果工具區。移除重複的結果跳轉；將通用 Grab 說明移入展開說明，保留可見短提示。條件採交集、支援單項移除與重設，列表與地圖顯示同一批結果。

### 店家卡片

第一層保留店名、飲食與有 Grab 標籤、距離、當日參考時段、簡短評分與地址，以及必要風險。

主要動作為導航；有官方 Grab 的店家同時提供 Grab 入口。收藏使用清楚的切換按鈕並呈現選取狀態。電話、地圖定位與詳細外部來源置於店家詳情。

將菜單、完整時段和詳細查核整理成一致的展開區，避免每張卡出現三種互相競爭的面板。Grab 回報、舊資料和待確認仍可閱讀；未知不改寫成沒有。保留分店辨識、來源、查核日期與證據日期。

### 換匯、補給、點餐

換匯先列主要選擇條件與結果，完整幣別查核放入詳情，保留交易限制提醒。補給卡先呈現圖片、品名與飲食判斷，成分／來源展開閱讀，採買勾選與放大圖片保持易用。點餐以出示大字卡為主，複製文字為次。

## 實作界線與驗收

沿用靜態網站與現有資料；重用核心搜尋、篩選、收藏和離線邏輯。只整理本次涉及的樣式與元件，避免再加入重複覆寫。維持 URL 返回、收藏與篩選保存、更新還原以及安全的歇業／地址衝突處理。

驗收涵蓋 320／390／768／1440px；無橫向溢位、固定導覽不遮主要操作、觸控目標至少 44px、鍵盤與展開狀態可使用。390px 附近頁預設狀態以首屏可見結果區／第一張卡片開頭為目標，必要警示不得為達目標而隱藏。

驗證搜尋＋全素＋Grab＋收藏交集、條件清除、每日帶入搜尋、列表／地圖切換、歇業保護、點餐與補給互動、離線與更新。執行 Node、Chrome 與 WebKit 適用測試、格式檢查與視覺截圖；更新快取版本與交付 ZIP。完成後提供前後差異與驗證結果；本次不自動提交或推送。
