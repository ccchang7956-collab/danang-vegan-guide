# Review 修正與優化設計

使用者已明確要求完成前次 review 的全部修正與優化，並指定可使用 Luna max 子代理、由主代理驗證。本設計直接執行該授權；工作區原為乾淨 main，採目前工作區分檔分工，不另建立工作樹。

## 行為與架構

- 沿用純靜態網站、原有資料、四個入口、Google 商家連結、GPS 僅在記憶體計算，以及既有手動選擇優先規則。
- 定位為共用的進行中請求。使用者在附近素食開始定位，再第一次切到換匯頁時，成功後應使用此次 GPS；選日期或手動地標仍取消舊請求，晚到結果不能覆盖使用者選擇。兩頁定位按鈕與等待提示均反映共用請求。
- 日期按鈕首次建立後保留節點，後續只更新 active、aria-pressed 和日期摘要。日期切換或 GPS 完成不得移除正在聚焦的日期按鈕。
- 每日及附近搜尋用 150 ms debounce，中文輸入組字中不重新建立結果；組字結束後套用搜尋。切頁、日期、清除、篩選與搜尋全清單必須取消舊排程或立即使用最新輸入，避免舊搜尋重畫其他頁面。
- 同頁的列表跳轉、地圖重設與卡片地圖操作，應先套用尚未完成的搜尋，維持輸入框與可見結果一致；不能取消排程後永久留下舊結果。若點選的舊結果已不符合搜尋，清楚提示重新選擇。
- 格式化自有 JavaScript 與 CSS，提供可重複的格式指令；不格式化第三方 Leaflet 或生成的 data.js。
- 開發驗證可加入 Playwright 與 Prettier devDependencies；發布仍無建置流程、API 金鑰或 npm runtime 相依。

## 驗證

- 先增加會失敗的定位時序回歸案例與搜尋計時案例，再修正行為。
- 用真實隔離的 headless Chrome 驗證鍵盤焦點、GPS 跨頁成功／手動選擇取消、中文搜尋、清除與跨頁 debounce、手機四入口與寬度。
- 離線測試覆蓋安裝失敗、成功後 skipWaiting、activate 僅清理本站舊版、快取未命中與網路失敗、非 GET／跨來源不處理。真實瀏覽器另驗證首次安裝、子路徑離線重載、worker 更新與不同 scope 快取保護。
- 所有既有測試必須通過；資料重新生成應與原 data.js 相同。服務工作執行緒更新為 v12，完整重建部署 ZIP 並逐檔比對。
- 主代理審查差異、執行驗證，記錄實際結果與裝置限制；更新 README 及 review 文件。不自動發布或推送。

## 設計自查

前次 review 的兩項問題與三項優化均有對應實作及驗證。搜尋延遲與取消規則明確；資料與部署方式保持一致。格式化、worker 測試與瀏覽器工具分別由不同代理負責檔案，最後整合由主代理進行。
