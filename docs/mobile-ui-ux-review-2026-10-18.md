# 手機旅行 UI／UX Review

日期：2026-10-18。對象：本機 v26，預計於峴港／會安旅途中以手機操作。

後續實作已完成於 v27，見 [交付與驗證記錄](mobile-travel-polish-2026-10-18.md)。下方保留修改前的觀察與量測。

## 判斷

現有視覺一致、閱讀清楚，底部五個入口也符合旅行任務。最值得改善的是「從打開頁面到完成導航／找到用餐備案」的速度，以及切換 App、重新載入後的連續性。

本次確認兩個可重現的操作缺口：一般重新整理會清掉搜尋及飲食篩選；首次直接進首頁的地圖缺少回列表按鈕。其他項目是根據實際畫面與程式行為提出的設計改善，不等於功能故障。

## 檢視範圍與限制

- 讀取 index.html、app.js、ux.js、core.js、兩份 CSS、service worker 與既有測試內容。
- 使用獨立無頭 Google Chrome 開啟本機網站，模擬觸控手機；檢查 320／390／430 × 844，以及 852 × 393 橫向尺寸的五個頁面。
- 實際操作搜尋、全素篩選、重新整理、地圖跳轉、空結果、點餐卡放大與離線重新載入。這不是完整自動化測試套件通過宣告。
- 畫面及座標以 CSS px 計算，手機瀏覽器網址列、實際字型與系統文字大小可能改變結果。
- 離線檢查使用專案現有測試伺服器；該伺服器會替換 worker 版本識別，能驗證本機閱讀流程，不能證明正式站部署版本或更新過程。
- 未實測實體 iPhone／Android、真實軟鍵盤、越南 GPS、戶外陽光、低階手機效能、真實行動弱網、Google Maps／Grab App 交接與螢幕閱讀器。未重新查核旅遊資料或正式站內容。
- 本輪只新增 review 與截圖，沒有修改網站功能或部署。

## 出發前優先改善

### 1. 保留一般重載前的搜尋條件【P1，已重現】

**情境：** 找好餐廳後切到 Grab、地圖或相機，瀏覽器重載頁面；或手動重新整理。

**證據：** 搜尋 `kurumi` 並開啟「只看全素」，重載前為 query=`kurumi`、diet=`vegan`；重載後 query 為空、diet=`all`。網址仍為 `#nearby?day=2026-10-21`。收藏本身有另外保存，不能與搜尋條件混為一談。

**原因定位：** `assets/ux.js` 的 persist 只存收藏、採買、列表／地圖模式與收藏篩選；搜尋 snapshot 僅在 `reload-update` 點擊時寫入 sessionStorage。`assets/app.js:1412` 已有可重用的 snapshot／restore。

**建議：** 保存非 GPS 搜尋條件、參考地標、日期／時間及目前店家；一般重載時恢復。日期／時間跨日後標示「上次查詢」並提供「改用越南現在時間」。不要偷偷將舊 GPS 當成新定位。

**驗收：** 搜尋、篩選、滑到特定卡片後重載，條件與閱讀目標仍在；新日期不被舊時間無聲覆蓋。

### 2. 首次進站的每日地圖沒有返回按鈕【P1，已重現】

**步驟：** 新開無 hash 的首頁 →「查看地圖」。`#map-list-return` 為 hidden=true。切到「附近素食」再回「每日行程」，重做同一步驟則 hidden=false。

**影響：** 地圖在很長的每日頁下方，初次使用者只能往上滑或再點底部每日入口；返回操作不一致。

**原因定位：** `index.html` 的按鈕預設 hidden；`assets/ux.js` 的 afterView 才切換顯示，而首次無路由的初始化沒有走同樣流程。navigateTarget 又以地圖標題而非整個工具列對齊，實測 map-panel 頂端約 -38px，重設工具的一部分被移出畫面。

**建議：** 初始化就設定返回按鈕；每日頁使用「回今日行程」，從店家進入則使用「回剛才的店家」。跳轉時確保整個地圖工具列可見。

**驗收：** 新進站、重載、跨分頁後、從店家進入四種路徑都有可見且符合來源的返回操作。

### 3. 首屏露出卡片，仍無法直接採取行動【P1，實測版面】

390 × 844 時，底部導覽從 y=772 開始：

| 頁面 | 第一張卡片開始 | 第一個導航按鈕開始 | 影響 |
| --- | ---: | ---: | --- |
| 找餐廳 | 618 | 934 | 首屏主要看到店名、評分；要再滑才能導航 |
| 換匯 | 701 | 1187 | 首屏只看到卡片標籤，連完整據點內容都需下滑 |

320px 寬時，找餐廳卡片從 702 開始、導航在 1041；換匯卡片從 829 開始、導航在 1401。既有「第一卡出現在某個高度前」的檢查不足以代表任務夠快。

**建議：** 找餐廳以搜尋、位置來源、主要篩選和結果為核心；將半徑與排序併入精簡控制區。換匯把日期／地標放入可展開的「依今日行程」摘要。卡片將導航提前至店名、距離、關鍵時段與警告之後，次要來源說明收合。

不要為壓縮卡片而隱藏蛋奶、魚露、歇業、地址衝突等會改變決策的警告。可以先收合純門牌寫法差異、查核方法與重複說明。

**建議驗收目標：** 390 × 844 預設頁面至少有第一筆店名、距離與導航可操作；若必要警告較長，優先保留警告。把「完成導航需要幾次操作」加入驗收。

### 4. 讓位置來源與定位新鮮度更清楚【P1，程式與畫面觀察】

**現況：** 初始依飯店排序，距離 badge 卻只顯示 `365 m・直線`；完整來源放在上方小字，地標選單會截斷飯店名稱。畫面標題是「找餐廳」，底部卻是「附近素食」。使用者若只看卡片，容易把距離理解成距自己。

定位採一次性的 getCurrentPosition；有精度顯示，但沒有取得時間，也沒有移動後自動更新機制。`maximumAge: 60000` 是再次呼叫時允許使用的快取年齡，不能保證頁面上的座標每分鐘更新。

**建議：** 在結果上方明顯顯示「以 Le Sands 飯店為中心」或「我的位置・3 分鐘前」，提供容易點的「更新定位」。卡片距離可標「距飯店／距定位」。回到頁面且定位過舊時提示更新；不必持續追蹤 GPS。

**驗收：** 未授權、拒絕、定位成功、過舊、手動選地標都有清楚的來源；停留一段時間後不仍暗示是即時位置。

### 5. 把「現在吃」做成前層任務【P1，設計改善】

**現況：** 已有「填入越南現在時間」，但藏在更多篩選中。預設列表沒有時間條件；所選日期要到卡片或展開篩選才明顯。使用者餓了時，需要自己組合定位、全素、日期和時間。

**建議：** 增加「現在找吃的」快捷，套用越南日期／時間及全素條件，位置使用現有授權定位或明示的參考地標。結果摘要固定顯示目前查詢的日期與時間。

仍用「依牌告時段推估」措辭；資料有衝突或接近打烊時提示先確認，不能宣稱即時營業。保留規劃其他日期的功能。

**驗收：** 一次點擊可進入明確的現在用餐情境，且不會把未知時段當作確定開門。

## 第二優先：降低閱讀與操作負擔

### 6. 每日頁提供「下一個任務」與回飯店捷徑【P2】

390px 畫面中，第一站在 y≈522，「今天怎麼吃」在 y≈1895，三餐區本身高約 1843px。頁面有用餐跳轉按鈕，已降低長頁問題，但從閱讀中的餐廳再找下一站或飯店仍需切回／滑動。

建議在每日日期下放精簡摘要：「今日住宿」「下一餐」「行程」。沒有明確時間的景點不應自動猜下一站，可讓使用者標記目前站點。三餐保留首選與備援，先展開目前需要的一餐；關鍵巴拿山警告繼續直接可見。回飯店導航可放在每日摘要，方便晚間使用。

保留目前五天日期切換、越南當日辨識與「回到旅行今天」機制；這些功能已存在，不需再重做。

[每日首頁](review-assets/2026-10-18/danang-review-daily.png)

### 7. 地圖圖釘重疊，難以用手指選店【P2】

每日地圖同時放景點、住宿和大量餐廳，實際畫面市區與海灘圖釘高度重疊。44px 的圖釘點擊區並不能解決互相遮住的問題。

建議每日地圖預設呈現行程與用餐首選，另提供「顯示其他餐廳」；附近頁可採群聚或僅突出選定店家。點圖釘後以固定的小卡顯示店名、距離與導航，避免多個浮窗互擋。地圖保持輔助定位角色，列表仍是預設入口。

### 8. 更多篩選展開後太長，缺少近手的完成操作【P2】

展開後包含日期、時間、現在時間、區域、飲食、Grab、營業查核及說明。390px 截圖中，飲食分類已靠近底部導覽，結果則更遠。搜尋 Enter 會跳結果是優點，但選下拉條件沒有同樣明顯的結束點。

建議使用底部篩選面板，或在現有展開區提供「查看 N 間結果／收合條件」按鈕。維持即時更新也可以，按鈕主要負責帶回結果；已啟用條件繼續顯示可移除標籤。

[展開篩選](review-assets/2026-10-18/danang-review-filters.png)

### 9. 收藏與全素偏好要符合個人旅程【P2】

「收藏 0」是開關，語意不如「只看收藏（0）」清楚；它與搜尋、Grab、全素交集使用，可能讓使用者以為收藏不見。現在已有空結果恢復功能，應保留。

建議保留「只看」語意，收藏頁面顯示哪些其他條件正在限制結果。這是全素旅行專案，可將全素設為可保存的個人偏好；需要確認蛋奶或葷素店保留明確的擴大搜尋入口。

### 10. 補給頁更適合用「待買清單」瀏覽【P2】

目前有圖片放大、越南文複製和已買標記，適合現場辨識。但每張卡高約 632px，11 件商品讓整頁約 9334px；門市區在 y≈7517，雖有「去哪裡買」捷徑，仍缺少逛店中持續可用的分類切換。

建議新增「未買／已買」與「需熱水／直接吃」快速篩選；商品列表採小圖＋名稱＋必要限制，點開才看大圖及詳細成分。保留品牌明確全素和成分判讀的區別。門市入口可放上方摘要，不能將線上商品資料當成當地分店有貨。

[補給頁](review-assets/2026-10-18/danang-review-supplies.png)

### 11. 點餐卡支援快速掃讀與橫向呈現【P2】

直向放大卡可完整閱讀，是目前完成度高的流程。橫向 852 × 393 時，字級隨寬度增加至 40px，整段內容需要捲動；使用者將手機交給店員時，對方未必知道下方還有內容。

建議依可用高度限制字級，提供簡短重點版和完整說明版。重點版以越南文分行呈現飲食限制，完整版本保留既有語意。任何越南文重寫均應另外校對，不在 UI 調整時自行省略限制。

## 視覺、可讀性與離線回饋

### 12. 小字、命名與狀態文案【P2／P3】

- 主要內容的深綠／米白與分區一致，值得保留。此次沒有做完整色彩對比稽核，不能斷言通過或不通過無障礙標準。
- 390px 的頁首網路狀態是 10px，底部文字約 11.2px，位置說明 12px；戶外掃讀時建議關鍵狀態 13–14px，主要決策內容 16px 左右，以空間和分層減少擁擠。
- 「找餐廳／附近素食」「換匯據點／換匯所」「全素點餐／點餐卡」命名可統一，降低學習成本。
- 「有 Grab」容易被理解為目前可外送。現有詳細說明有交代官方入口的限制，但可將短標籤直接改為「Grab 入口」。
- 網路狀態的長句在右上角換行，字很小。建議簡短顯示「離線可讀」或「正在準備離線」，點擊打開可閱讀的說明面板；目前說明使用 3.5 秒 toast，長句不易讀完。
- 已實際確認離線重載仍顯示 44 張餐廳卡。這是優點，但「離線功能啟用」不代表地圖、Grab 或導航可離線使用；現有提示應保留，並在離線點外部動作時給就地回饋與可複製的店名／地址。
- 首次開啟時，initMap 即建立底圖；可評估地圖接近視窗或按下地圖才載入，降低先看文字時的網路需求。本輪未量測弱網載入時間，不宣稱有實測速度提升。

## 本次確認值得保留的部分

- 五個固定底部入口，能隨時切到點餐卡。
- 上述四組尺寸、五個預設頁面均未量到水平溢出。
- 抽查主要導航按鈕高 44px；採買 checkbox 雖只有 24px，外層 label 有至少 48px，不能只看 checkbox 大小就判定難點。
- 搜尋 Enter 會收回輸入焦點、前往結果；無結果有清除關鍵字及重設入口。
- 列表／地圖切換、收藏、商品已買標記、越南文複製與商品放大已有基礎。
- 卡片對不確定營業、飲食與地址資料有明示，沒有假裝所有資訊都即時可靠。
- 離線閱讀與本機偏好保存已存在。

## 建議實作順序

1. 修正一般重載的搜尋保存，以及首次地圖返回按鈕。
2. 精簡找餐廳／換匯控制區，提前第一筆可操作導航；明示位置來源與定位時間。
3. 加入「現在找吃的」、今日住宿／下一餐捷徑，縮短現地決策流程。
4. 改善地圖重疊、篩選完成入口、未買清單與橫向點餐卡。
5. 最後統一命名、調整小字與離線狀態文案。

出發前應以自己的手機走一次：飯店 Wi-Fi 開站 → 開飛航模式重載 → 找收藏餐廳 → 開點餐卡 → 恢復連線定位 → 切到 Google Maps／Grab → 返回原店家。這能補上本次模擬環境無法確認的 App 交接、真實 GPS、鍵盤與安全區行為。
