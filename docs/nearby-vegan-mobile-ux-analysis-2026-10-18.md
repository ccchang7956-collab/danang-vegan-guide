# 手機「一鍵找附近全素」UI／UX 分析

日期：2026-10-18。以下保留分析與改版建議；後續已依使用者「按照你建議的幫我改」實作為本機 v29，尚未部署。見[交付記錄](nearby-vegan-delivery-2026-10-18.md)。

## 需求與檢視範圍

使用者已確認：手機開啟以附近全素優先，每日行程放次要入口。沿用專案飲食需求：全素，五辛可接受。

本次閱讀目前本機 HTML、CSS、app.js、ux.js、core.js、manifest 及既有改版紀錄，並使用 Chrome 裝置模擬檢視 393 × 852 的每日首頁與找餐廳首屏。沒有重新執行測試套件、取得真實 GPS、查核店家資料或確認正式站部署版本；模擬畫面不等於實體 iPhone 測試。

核心目標：開啟網站 → 一次點擊找附近全素 → 看見可比較的候選 → 再點一次開啟導航。首次或權限失效時，另需瀏覽器定位授權；導航 App 可能另有啟動步驟。

## 現況判斷

目前深綠／米白視覺、卡片、底部導覽、全素點餐卡與離線內容可沿用。現有版本已做搜尋狀態保存、位置取得時間、全素偏好保存、首筆導航提前與更多條件收合，不應重複列為尚未完成。

主要改善點是首頁優先順序、定位與時間操作的整合，以及結果是否真正符合「附近、現在、全素」。

| 目前行為 | 對旅途中操作的影響 | 建議 |
| --- | --- | --- |
| 初次無路由進站以每日行程開始 | 要先切換找餐廳，再組合其他動作 | 新開首頁先進附近全素；明確的行程連結與從外部 App 返回的狀態仍優先 |
| 「現在找吃的」與「使用定位」分開 | 點現在吃不會取得或更新 GPS | 合成主要動作「找我附近的全素」 |
| 現在吃已清除關鍵字、區域、Grab、收藏限制，但保留半徑及位置 | 可能仍查舊地標、舊 GPS 或先前過窄的範圍 | 重新建立明確的現在附近查詢，不繼承規劃模式的半徑 |
| 附近範圍初始為不限距離 | 全清單、遠方餐廳與附近語意不一致 | 預設 3 km，提供 1／3／5 km；結果不足時明示擴大 |
| 查詢初始日期沿用旅行日 | 出發前或日期切換後不一定在看當下 | 現在附近使用越南當日當下，規劃日期另設入口 |
| 有時間時已依供餐狀態排序，但不在時段內的店仍混在列表後方 | 餓的時候仍須逐店辨識能否用餐 | 分成依牌告時段可用餐、需確認、稍後／其他時段 |
| 定位失敗會改依行程地標排序 | 雖有說明，仍可能將預設飯店理解為自己附近 | 顯示持續可見的失敗狀態，提供重試與選地標；地標結果明確改名 |
| 首屏先有搜尋、三個快捷、兩個任務按鈕、更多條件、列表／地圖與摘要 | 未知店名時仍先面對多個選擇 | 主動作與結果提前；搜尋與進階篩選改為次要入口 |
| 地圖即使不是主要閱讀區仍會初始化 | 列表任務仍可能產生地圖工作與圖磚請求 | 第一次打開地圖時再初始化；成效需另量測 |

程式依據：`assets/app.js` 的初始 view、origin、renderNearby、locate、eat-now handler、renderMap；`assets/core.js` 的 restaurantHours、mapsUrl；`assets/ux.js` 的 session／偏好保存；`index.html` 的附近頁控制順序。

## 三種改版幅度

| 方案 | 改動與取捨 | 判斷 |
| --- | --- | --- |
| 首頁改成附近，合併定位按鈕 | 改動最小，但既有控制項仍擠在結果之前 | 可作第一階段交付 |
| 附近全素任務首頁 | 整合定位、時間、飲食與範圍，先顯示少量精簡卡片，進階條件按需展開 | 最符合已確認的使用情境，推薦 |
| 全螢幕地圖首頁 | 空間關係直覺，但圖釘操作、弱網底圖與飲食資訊閱讀更複雜 | 作為可切換模式，不優先 |

## 推薦的手機介面

由上而下：

1. 精簡頁首：「附近全素」及離線狀態。
2. 首次使用顯示整列大按鈕「找我附近的全素」，下方說明會使用位置與越南現在時間；旁邊或下一行提供「改用飯店／景點」。
3. 成功後收斂為位置摘要：「我的位置・剛剛更新」「越南 12:15・3 km」，提供更新定位。
4. 精簡控制列：範圍、篩選、地圖；搜尋店名可展開。全素是清楚顯示的預設條件。
5. 優先顯示最多三間符合目前條件的候選，再提供「查看全部 N 間」。三間是候選展示數，不代表一定有三間，也不是評分最高保證。
6. 底部導覽依次為「附近、行程、點餐卡、補給、換匯」。收藏保留在附近頁的次要入口。

未定位時不可預先把飯店距離叫作「距你」。可以展示明確標示的飯店附近預覽，或直接給選地標入口。

定位成功後主按鈕變成精簡「更新位置」，避免永遠佔據大塊首屏。從其他分頁點附近先恢復閱讀狀態，不應每次切頁便自動清空或再次跳定位授權。

## 一次點擊應完成的行為

1. 進入附近列表模式，清除舊的關鍵字、區域、Grab、收藏限制及用餐規劃條件。
2. 套用全素、越南當日當下與預設 3 km 範圍。
3. 取得目前位置，或使用年齡與精度都可接受的近期定位；顯示來源與取得時間。位置誤差若接近搜尋半徑，應提示重新定位，不把細小距離差距當成可靠排名。
4. 在範圍內排除已歇業、地址暫停導航者作為主要候選，按供餐資料可信程度分組，再於同組依直線距離排序。
5. 顯示候選與清楚的導航動作；定位處理狀態、結果更新與錯誤需可被螢幕閱讀器讀到。

「現在找吃的」既有清除篩選邏輯可以重用；不是所有邏輯都要重寫。

## 結果排序與標籤

- 首組：全素、有可用座標、無導航地址衝突、已有營運依據且目前落在牌告供餐時段。
- 接近時段結束者明示「30 分鐘內結束，先確認供餐」；既有 core.js 已支援此狀態。
- 時段衝突或缺資料者另列「需確認」，提供電話；不假裝確定開門，也不整批隱藏到找不到。
- 未到時段、午休與當日休息者列在可展開的「其他時段」；歇業紀錄留資料查核功能。
- 無座標者維持「距離未確認」，不計入已確認的 3 km 結果數。
- 三公里無主要候選時明示「本站整理的店家中，3 km 內沒有符合目前條件的全素店」，提供擴大到 5 km、查看需確認店家或其他時間。
- 若自動擴大範圍，必須同步更新畫面的範圍與摘要。飲食條件不因結果為零而自動放寬。
- 定位離峴港／會安很遠時顯示地區限制，提供行程地標預覽；不將跨區遠店稱為附近。

資料來源仍是本站收錄清單，並非搜尋當地所有餐廳。未收錄不代表當地沒有素食。

## 餐廳卡片與手持閱讀

精簡卡片的順序：易辨識店名／分店、距定位的直線距離、全素分類、供餐狀態、必要警告、導航。菜色與價格有資料才顯示；不能用單一品項價格推成平均消費。

全名過長可使用可辨識的顯示短名，但保留分店／地區，詳情與導航保留商家全名及地址。蛋奶爭議、地址衝突、即將打烊等會改變決策的訊息維持前層。

沿用深綠／米白。主要內容以約 16 px 為起點、次要狀態約 14 px；以減少重複文字取得空間。主按鈕建議 48–56 px 高，互動區至少保有目前多數元件的 44 px。狀態使用文字配色，避免只有綠／黃點能辨識。

首屏目標為完整可操作的第一張候選卡；一般資訊量下爭取露出第二張。不能為固定高度截掉必要警告，也不能犧牲手機放大文字後的閱讀。

## 定位、導航與離線

- 首次或權限失效需使用者允許定位；網站無法承諾完全略過系統詢問。依 MDN，Geolocation 需要安全環境及使用者授權。
- 等待定位時立即顯示「正在取得位置」，防止重複請求並提供地標備案。現有 12 秒 timeout 可沿用為起點；實際等候策略需實機評估。
- 定位失敗時，不把備案地標悄悄包裝成定位成功；拒絕、逾時與精度不足應有對應下一步。
- 返回網站時恢復原店家與捲動位置，位置過舊提供更新入口。現在模式的時間也應重新檢查，不長時間保留午餐狀態；避免未告知即重新排序造成卡片跳動。
- 直線距離不能換算成步行時間或可步行保證，尤其跨河、山區與園區。導航交給 Google Maps，必要時可增加步行／開車選擇。
- 現有 mapsUrl 已使用 Google Maps URLs，不需為基本外部導航改成付費地圖服務。官方支援 destination 及 travelmode；實際開啟 App 或網頁依裝置而定。
- 離線店家資料與點餐卡沿用現有快取；導航、Grab 與外部地圖需另處理連線。可提供複製店名／地址及明確的資料查核日期。
- 地圖延後載入是降低列表頁工作量的方向；本次沒有弱網效能數據，尚不宣稱已改善速度。
- 加入手機主畫面的入口可使用現有 manifest；應同步調整預設路由與啟動行為，避免圖示開啟又回每日頁。

## 實作優先順序與驗收

第一階段：預設附近首頁、單一主要動作、明確定位狀態、全素與越南現在時間、固定預設範圍。這組先讓需求成立。

第二階段：精簡候選卡、供餐分組、空結果處理、首屏控制層級與底部導覽排序。這組讓結果更容易選。

第三階段：地圖延後載入、主畫面啟動、實體手機 App 往返與弱網微調。這組改善現地連續使用。

未來驗收至少涵蓋：

1. 新開首頁不必切頁、輸入店名或展開篩選即可啟動附近全素。
2. 已有定位授權的正常情境，一次網站操作得到結果，再一次操作開啟選定店家的導航。
3. 首次授權、拒絕、逾時、舊定位、低精度、旅遊地區外與離線，都有明確狀態與可用下一步。
4. 主流程固定使用當下飲食與時間條件，不受上次 Grab、收藏、區域或舊半徑意外限制。
5. 零結果保留全素要求；擴大距離、改地標、查看需確認店家都清楚標示。
6. 320／393／430 px 寬度及大字體下無橫向溢出，底部安全區不遮導航；一般首屏至少有一間完整可操作候選。
7. 從 Google Maps／Grab 返回仍停留原餐廳；開啟規劃行程的明確連結不被預設首頁搶走。
8. 地圖不出現時文字列表仍能使用；更新快取後可在實體手機辨識新版並驗證離線閱讀。
