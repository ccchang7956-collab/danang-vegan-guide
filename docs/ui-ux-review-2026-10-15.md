# UI／UX review（2026-10-15）

## 範圍與結論

檢視 `index.html`、`assets/app.js`、`assets/core.js`、`assets/styles.css`、`sw.js`，並以本機 Chrome 桌面與 393 × 852 裝置模擬檢視五個入口。實際搜尋 `roots` 得到 1 間，檢視搜尋欄與餐廳卡片畫面。本文是 review 與建議，未修改網站程式。

優先改善搜尋回饋、結果可達性、篩選可預期性與點餐操作。整體米白／深綠配色、字體與插畫已有一致性，適合沿用。最大空間在資訊順序：使用者需先讀過介紹、查核與地圖，才能到達真正要操作的內容。

證據標示：**畫面＋程式碼**代表本輪實際看到並核對實作；**程式碼**代表由靜態實作判讀；**產品提案**代表可選的新能力。優先級 P1＝建議下一輪先做；P2＝接續優化；P3＝有需求再加。工作量為相對估計，小／中／大，不代表時數承諾。

## P1：建議先做

### 1. 搜尋欄旁持續顯示結果數與搜尋範圍（小）

- 證據：畫面＋程式碼。`app.js:290`、`:308` 採輸入後 150 ms 更新；沒有獨立的搜尋送出流程。附近頁結果數在 `index.html:58`，每日頁在 `:48`，都離搜尋控制項很遠。搜尋 roots 後確實有 1 間，但搜尋欄所在畫面看不到。
- 影響：難以知道搜尋是否生效、是否沒資料，尤其每日頁還隔著地圖及景點行程。
- 建議：在搜尋欄下持續顯示「找到 1 間 · 依 Le Sands 飯店排序」或「10/22 · 整天行程 10 km 範圍 · 找到 N 間」，附「查看結果」。加上「輸入即搜尋」，手機搜尋欄使用整列寬度。
- Toast 適合補充明確送出搜尋、複製、匯出等動作；不建議每輸入一個字就跳一次。若加入 Enter／鍵盤搜尋送出，該動作可收起鍵盤、完成搜尋並提示結果。零筆時須有持續顯示的訊息。
- 驗收：搜尋、清除、變更範圍或篩選時，搜尋欄附近的數量與列表一致；中文組字期間不打斷輸入；不重複朗讀多個相同 live region。

### 2. 手機提供真正的「列表／地圖」模式（中）

- 證據：畫面＋程式碼。`index.html:38–48`、`:58`、`:72` 的窄螢幕 DOM 順序都是地圖先於列表。現有「查看列表」只是捲動跳轉，沒有切換呈現模式。
- 影響：每次篩選後仍需跨過地圖；每日頁更要跨過景點，才能看到餐廳。
- 建議：附近素食與換匯頁手機預設列表，提供分段控制「列表／地圖」，切換保留條件與選取店家。每日頁以行程為主，餐廳搜尋送出後提供直接查看結果的入口。桌面保留目前地圖與列表並排。
- 驗收：列表模式不占地圖高度；地圖模式同步相同結果；切換不清掉關鍵字、參考位置或篩選。

### 3. 「只找全素店」保留其他篩選條件（小）

- 證據：程式碼。`app.js:1038` 同時清空搜尋、區域與營業查核，然後設定全素。
- 影響：搜尋某店或選會安後按此鈕，範圍會突然擴大；按鈕文字無法預告這些副作用。
- 建議：改為可切換的「只看全素」篩選，保留搜尋、區域與營業條件，提供明確選取狀態。另設「重設全部條件」。若要維持目前一鍵探索行為，需換成能清楚說明重設範圍的文案。
- 驗收：選會安並輸入關鍵字後，開啟全素只改飲食條件；關閉可回復原飲食選項。

### 4. 零筆結果提供直接可按的解法（小～中）

- 證據：程式碼。`app.js:454`、`:470` 的 empty state 目前只有文字。附近頁沒有全條件重設按鈕。
- 影響：使用者得滑回上方並猜哪個條件限制了結果。
- 建議：顯示目前條件，提供「清除關鍵字」「重設篩選」；每日頁再提供「擴大到 15 km」「改搜全清單」。按鈕明確說明將改變哪個條件。
- 驗收：錯字、多重條件、每日範圍不足都能在空狀態直接恢復；不要自動放寬全素條件。

### 5. 點餐卡把「放大／複製」移到全文之前（小）

- 證據：畫面＋程式碼。`index.html:78–79`，操作列在越南文、英文、中文全文之後。393 × 852 首屏看不到放大按鈕。
- 影響：正在櫃檯溝通時，最需要的動作反而要滑很遠。
- 建議：主標題下立即放「放大給店家看」，旁邊「複製越南文」；英文、中文改成可展開的對照。複製的語言要與按鈕文字一致，目前複製的是越南文＋英文。
- 驗收：進入點餐頁不需捲動即可放大；對話框關閉後焦點回到觸發按鈕；關閉入口在長文捲動時仍容易找到。

### 6. 縮短餐廳卡片，把決策資訊與操作排前（中）

- 證據：畫面＋程式碼。`app.js:103` 的卡片依序放分類、距離、店名、查核狀態、日期、評分框、地址、飲食說明、每週時段與通用提醒，最後才是導航。Roots 卡片在手機上占據接近一個可用畫面高度。
- 影響：很難快速比較多家店，也不容易立即導航。
- 建議：收合狀態保留店名、全素條件、距離與基準、精簡評分、當日參考時段、地址摘要及導航。完整每週時段、歷史地址與查核沿革放詳細資料。一般提醒在列表上方統一說明；店家特有的蛋奶、搬遷、歇業與時段衝突警示仍需直接可見。
- 驗收：使用者不展開詳細資訊即可判斷是否適合與如何前往；關鍵飲食風險不能因收合而消失；Google 完整店名仍可查閱與複製。

## P2：接續改善

### 7. 篩選顯示摘要與可移除條件（中）

- 證據：畫面＋程式碼。`index.html:55` 的搜尋與參考地標各只占半列，名稱與 placeholder 被截斷；多個 select 缺乏集中摘要。
- 建議：搜尋整列；常用「全素／區域」直接呈現，營業查核放進進階篩選。結果上方顯示「會安 ×」「全素 ×」與「重設」，讓有效條件一眼可辨。只有 46 筆資料，暫不需要分頁或無限捲動。

### 8. 把匯出與查核沿革移出找餐廳的主路徑（小）

- 證據：畫面＋程式碼。`index.html:56–58`，Google 我的地圖匯出、匯入說明與全資料查核統計位於結果之前。
- 建議：匯出放進「更多／資料與匯出」，完整說明按需展開。結果附近優先放本次找到的數量，資料總數與查核資訊留在說明區。匯出仍明確標示包含歇業且不受篩選影響。

### 9. 每日行程優先顯示日期與路線（小～中）

- 證據：畫面＋程式碼。首頁手機首屏包含品牌、離線標籤、hero、旅行統計與第二組介紹，再到日期與操作。
- 建議：縮短每日頁介紹，讓日期、當日路線與主要操作更早出現。出遊期間可依越南日期預選對應一天；旅行前後顯示明確日期，不把非旅行日稱為今天。可以加「回到今天」；保留手動選日優先權。
- 備註：自動日期屬產品提案，需處理越南與台灣跨日。

### 10. 整天行程距離標示是哪個地標（中）

- 證據：程式碼。`app.js:417` 計算到當日多個景點／住宿的最小距離，`distanceText` 只呈現「N km・直線」。附近頁排序也有營業查核與全素優先，並非只按距離。
- 影響：可能把「離整天路線某一站近」理解成「離我近」，或不理解為什麼較遠店家排在前面。
- 建議：每日卡片寫「距韓市場 800 m・直線」；附近列表明示目前基準。增加「全素優先／距離優先」排序選項時仍保留歇業與待確認狀態的清楚區別，不預設新增評分排序。

### 11. 分頁切換保留閱讀位置，支援返回與分享（中）

- 證據：程式碼。`app.js:788` 只維護記憶體 view，`:1062` 每次點底部導覽都回頂端；沒有 URL／history 對應。搜尋、日期與位置在重新載入後回預設。
- 建議：每個入口保留自己的捲動位置，同入口再次點擊才回頂端。以 hash 或 query 記錄頁別與日期，支援返回鍵和分享指定一天。可以保存非敏感偏好；GPS 維持不持久化。
- 驗收：餐廳列表 → 點餐卡 → 返回附近頁，可回到原卡片；重新載入與瀏覽器返回對應到合理畫面。

### 12. 換匯先選需求，再讀推薦說明（小～中）

- 證據：畫面＋程式碼。`index.html:63–72`，長推薦框在定位與幣別控制前；手機首屏看不到幣別篩選。卡片也有多層說明。
- 建議：將 TWD／USD／全部幣別放前面，旁邊可直接切定位／行程地標，接著顯示結果數及列表；推薦說明改為簡短摘要或展開區。卡片優先顯示幣別資料、分行確認狀態、服務時段與電話／導航。
- 驗收：明確區分銀行有幣別資料與分行當日受理；不把改版後的簡短文字寫成收鈔保證。

### 13. 新版提示改成可持續操作的通知（小～中）

- 證據：程式碼。`app.js:70` 所有 toast 固定 3.5 秒消失；`:1114` 新版下載只用 toast 要求重新整理。
- 建議：新版提示使用可關閉的常駐橫幅「新版資料已備妥」「重新載入」，保留目前非 GPS 條件。一般複製成功用短 toast 即可；匯出匯入步驟保留在可再次閱讀的說明內。
- 驗收：錯過提示後仍能找到更新操作；只在使用者選擇後重載，避免打斷輸入。

### 14. 地圖與列表跳轉補上返回路徑及焦點（中）

- 證據：程式碼。`app.js:524`、`:1052` 以 `scrollIntoView` 跳轉，卡片只有短暫 outline，未把焦點移到目的標題；所有餐廳圖釘以「葉／!」重複表示。
- 建議：「在地圖看」後保留可返回原卡片的操作；「查看結果」把焦點移到列表標題；分頁切換使用一致的標題焦點策略。圖釘選取加明確外框／形狀，密集區域視需要採聚合或選取卡，維持文字分類。
- 備註：本輪未使用實體 VoiceOver 或鍵盤完整遍歷，不宣稱通過完整無障礙稽核。

### 15. 超市補給用包裝圖快速辨認，再展開詳細說明（中）

- 證據：畫面＋程式碼。11 款商品各帶圖片、成分、提醒與庫存說明；圖片點擊開新分頁。`index.html:130` 的 AEON 仍寫「上列六款」，與目前 11 款不一致；WinMart 文字有「未确认」。
- 建議：先顯示包裝圖、品名、判讀等級與「直接吃／需熱水」，成分展開。圖片使用站內放大對話框，附複製越南文名稱與回到商品功能。維持「品牌明確全素」和「依成分判讀」的差異。同步修正六款等過期文字。

## P3：有明確需求再加

### 16. 收藏餐廳與採買清單（中，產品提案）

旅途中需要再次找到選過的店家或商品。可先做本機收藏、已買勾選與「我的收藏」篩選；只有個人旅行用途時不需帳號或跨裝置同步。狀態變更用短 toast，取消收藏可提供復原。資料更新仍以穩定 ID 對應。

### 17. 精簡提示狀態與視覺層級（小～中）

卡片內多種綠底徽章、框線和說明框同時競爭注意力。建議主操作維持深綠；全素分類使用短徽章；一般查核日期與評分改成次要文字；僅需採取動作的風險用醒目警示。字級維持可讀，不以縮小所有文字換取密度。頁首狀態可縮成「可離線閱讀」，點開再看地圖限制與加入主畫面說明。

### 18. 整理樣式覆寫，維持後續一致性（中，程式碼）

`styles.css` 的 `.diet-badge`、`.card-top`、`.small-note`、`.site-header` 等有多次後段覆寫，手機規則也散落。這讓調整卡片或字級時不容易掌握最終結果。建議在視覺行為決定後，整理基礎字級、間距、按鈕與徽章，再集中各斷點規則；搭配頁面比較確認外觀，避免只做清理卻意外改版。

## 建議執行順序

1. 搜尋欄旁結果摘要、零筆解法、全素切換保留條件、點餐操作前移（1、3、4、5）。
2. 手機列表／地圖切換、餐廳卡片精簡、篩選摘要（2、6、7）。
3. 閱讀位置與返回、換匯順序、更新橫幅、超市圖片操作（11、12、13、15）。
4. 再依實際使用需求加入收藏，整理剩餘視覺與樣式。

## 已有基礎與限制

已有五入口固定導覽、明確選取狀態、多處 44 px 以上操作區、16 px 表單字級、中文組字處理、來源展開、定位失敗備援、空狀態文案、點餐 modal、離線提醒與 reduced-motion CSS，這些適合延續。

本輪沒有改功能、執行自動化測試、向外部服務送出資料或重新查核餐廳／銀行資訊。未實測實體 iPhone Safari、軟鍵盤、安全區、當地 GPS、弱網或離線更新流程；相關項目是程式碼判讀與待驗證的改版驗收條件。對照與配色未做正式對比值量測。畫面證據以本輪 Chrome 裝置模擬為準。
