# Review 修正與優化結果

使用者授權完成前次 review 的全部修正與優化。由三個 Luna max 子代理分別處理前端、離線與瀏覽器工具，主代理審查差異、處理整合問題並獨立執行最後驗證。瀏覽器代理達額度上限後，最後的測試調整與交付由主代理完成。

## 修正與優化

| 問題／情境 | 完成後行為 |
| --- | --- |
| 附近素食開始定位，完成前第一次切到換匯頁 | 換匯頁繼承此請求，成功後以 GPS 排序；兩頁等待狀態與按鈕同步 |
| 定位進行中改日期或手動地標 | 取消舊請求的效力；晚到回覆不覆蓋手動選擇 |
| 換匯明確選過手動路線，再從附近素食定位 | 保留換匯的手動模式，不把新 GPS 強加到換匯頁 |
| 按日期或 GPS 回覆導致日期按鈕重建 | 保留原按鈕節點，只更新 class 與 aria-pressed，鍵盤焦點不會遺失 |
| 每次輸入都重建卡片與圖釘 | 搜尋等待 150 ms，連續輸入只套用最後一次；中文組字期間不因輸入重繪 |
| 搜尋排程尚未完成就清除、改範圍／地標、篩選或切頁 | 取消或立即套用排程，避免舊搜尋重畫隱藏頁面；操作使用最新輸入 |
| 同頁地圖／列表跳轉取消搜尋，永久留下舊結果 | 先套用目前搜尋，再執行跳轉；被搜尋移出的舊卡片有明確提示 |
| 搜尋更新後選餐廳，自動 fitBounds 蓋過 zoom 16 | 卡片操作更新圖釘時不安排自動縮放，選取位置與彈窗維持可用 |
| fetch 成功，但 cache.put 失敗後回傳網路錯誤 | 保留成功網路回應；快取寫入失敗不阻止線上內容 |
| 原始碼整段壓在單行 | 格式化自有 JS/CSS 與測試，餐廳／換匯卡片模板分段，加入可重複的格式指令 |
| 模擬 DOM 無法驗證真實焦點與 worker 更新 | 加入隔離 headless Chrome 測試、真實 CacheStorage／worker 生命週期與手機尺寸檢查 |

主要前端修正在 [assets/app.js](../assets/app.js)，離線修正在 [sw.js](../sw.js)。`assets/core.js` 與 `assets/styles.css` 的內容與原檔經同一 Prettier 設定處理後完全一致，確認為格式化變更。第三方 Leaflet 未改寫。

## 最後驗證

| 指令／檢查 | 結果 |
| --- | --- |
| `npm test` | 84／84 通過：12 核心、11 資料、10 離線、51 UI |
| `npm run test:browser` | 12／12 通過：10 真實 DOM／UI、2 真實離線生命週期 |
| `npm run format:check` | 全部符合格式 |
| `node --check` | 14 個自有 JavaScript／配置／測試檔案通過 |
| `git diff --check` | 通過 |
| `python3 scripts/build-data.py` | 成功；生成的 data.js 與修正前逐 byte 相同 |

瀏覽器為本機 Google Chrome 155.0.8059.79，使用獨立 headless 程序與臨時瀏覽器環境。手機尺寸為 393 × 852；四個入口無水平溢位，實際操作餐廳地圖按鈕、放大與關閉點餐卡，並人工檢查六張畫面。真實離線測試驗證 `/trip/` 子目錄安裝、離線重載，以及新版 worker／新版 HTML 快取生效後不刪除 `/other/` 的快取。

另在隔離的測試請求中暫時載入修正前 app.js，確認兩項瀏覽器回歸都能抓到原始問題：切日後焦點斷言失敗；換匯定位選單仍為 route 而非 gps。測試檔隨後逐 byte 恢復為已通過完整驗證的版本，舊程式攔截不保留在專案或 ZIP。

GPS 回覆與圖磚在測試中受控制；DOM、Leaflet 實例、定位回覆後的 UI、service worker 和 CacheStorage 都使用真實瀏覽器機制。瀏覽器測試起初因沙盒禁止 localhost bind 而無法啟動，最後使用已批准的隔離測試環境完成。

測試中修正了虛擬時鐘的安裝時序：必須在網站與 Leaflet 載入之前安裝，再於需要時暫停；依 [Playwright 官方 Clock 文件](https://playwright.dev/docs/clock)。地圖彈窗會依 Leaflet autoPan 調整視野，檢查 zoom 16、選取點仍可見、正確彈窗及可操作內容在地圖內，不誤把正常 autoPan 當成缺陷。Node 輸出的 NO_COLOR／FORCE_COLOR 色彩設定提示來自執行環境，不影響測試結果。
